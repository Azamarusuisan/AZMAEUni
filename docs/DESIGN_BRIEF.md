# DESIGN_BRIEF — Note Draft Pipeline 導入・運用マニュアル
承認: ユーザー / 2026-08-04 / 版: v10

## 1. 主題
- 対象: Codex・Claude Code・Hermesで、記事制作を依頼から未公開下書きまで進めるAgent Skillの導入・運用マニュアル
- 読者: Claude CodeやCodexに興味を持って導入したが、まだ本格的な活用像を持てていない人。細かな実装より「結局、自分に何ができるようになるか」を先に知りたい。Windows購入者はPythonの版、PowerShell、OneDrive、WSL、会社PCの制約を自分で切り分けられない前提で案内する。主にPCで閲覧するが、スマートフォンでも結論からトラブル解決まで読めること
- 唯一の仕事: 読者が30秒以内に導入後の成果を理解し、「自分もこれを使いたい」と判断できるようにする
- 成功指標: ファーストビューとその直下だけで、入力、Skillが行う仕事、最終成果物、非対応範囲を説明できる。官公庁・論文・企業IR・ニュース・技術情報・SNSなどを問いに応じて調べられること、日本のnote、英語圏のReddit、中国語圏のBaidu系サービスを経験・反対意見・現地語彙の探索に使い、重要事項は元の一次情報へ戻ることを技術知識なしで理解できる。無料記事だけでなく無料部分と有料部分を持つ記事、価格案、有料ライン案まで作れること、ただし公開・販売開始はしないことを理解できる。文字入りアイキャッチと記事内図解の実例を見て、完成像を技術説明なしに理解できる。画像生成とCMSへのファイル送信が別能力であり、画像不足時は「下書き保存完了」ではなく `save_unverified` と表示されることをトラブル欄で理解できる。別PCや別Agentから受け取った記事フォルダ／ZIPは、同梱プロンプトを信用せず画像・hash・MIME・秘密情報を検査してから取り込めること、完成runはアカウント情報を除いたZIPへ書き出せることを理解できる。初回セットアップではエージェントがChrome／Safariを必ず質問し、利用者の回答前にブラウザを勝手に確定できないことがコマンド例と会話例の両方で分かる。公開URLを開くだけでマニュアルを閲覧できる。Codex購入者はGitHub URLを含む2コマンドでPluginを導入できる。Windowsタブでは、購入者が一つのDoctorコマンドから環境固有の修正手順へ進める。320px、375px、430pxでページ全体の横スクロールがなく、OS名が欠けず、主要操作のタップ領域が44px以上ある

## 2. 審査
- 最終判断者: ユーザー本人
- 過去のNG: 工程や技術の説明が先行し、導入すると何ができるようになるかという結論が目立たない
- 過去のOK: 現行マニュアルの落ち着いた配色、可読性、OS切替、実行例を残す
- 経由するレビュー: ユーザー本人の確認

## 3. 世界観
- 題材の固有物: 一行の依頼、調査メモ、記事原稿、アイキャッチ、未公開下書き、検証レシート
- ブランド人格: 技術を見せびらかさず、完了物を机の上に並べて説明する実務担当者
- 参照: 現行HTML — 落ち着いた編集マニュアルの体裁と可読性を継承
- 反面教師: 機能名や環境要件から始まり、読者が自分の成果を想像できない技術ドキュメント
- 業界の型: SaaS風の機能カード列挙は避ける。実際の「依頼→作業→成果物」を一つの仕事票として見せる
- 一次素材: 実機スクリーンショットを操作の証拠として使う。生成画像は、Skillが作れる文字入りアイキャッチと記事内図解の実例に限定し、「生成例」と明示する。疑似的な製品画面や実在しない操作結果には使わない

## 4. トークン

### Color
既存のトークンを維持し、新色を追加しない。

- `--ink: #14201c` 本文
- `--bg: #ffffff` 地
- `--accent: #0f8a72` note・完了の強調
- `--brain: #a8620a` Brain固有
- `--warn: #b4472c` 禁止・未対応
- `--surface: #f6f8f7` 補助面

ダークモードも現行の対応値を維持する。

### Type
- Display: ヒラギノ明朝／游明朝 — マニュアルの編集物らしさを継承
- Body: ヒラギノ角ゴ／游ゴシック / 行長目安: 全角35〜45字 / line-height: 1.9前後
- Data/Caption: SFMono系 — 成果物名、状態、コマンドだけに限定
- 和欧混植: 現行のフォールバック順を維持し、見出しでは `text-wrap: balance` を使う

### Layout
- コンセプト: 「機能一覧」ではなく、テーマ一行が未公開下書き一式になる仕事票
- 密度: 中。最初の30秒は余白を確保し、既存の詳細マニュアルは高密度のまま残す
- ワイヤー:

```text
┌────────────────────────────────────────────┐
│ テーマを一行伝える                         │
│ 「○○についてnoteを書いて」                │
│                                            │
│ ↓                                          │
│ 調査 → 構成 → 執筆 → 画像 → CMS → 再確認  │
│                                            │
│ 最後に残るもの                             │
│ 未公開下書き / 原稿 / 画像 / 出典 / 検証記録│
│                                            │
│ できること ｜しないこと｜Brainの現在地     │
└────────────────────────────────────────────┘

以降：00 読み方 → 現行マニュアル
```

### Signature
- このページが記憶される唯一の要素: 「一行の依頼」が「未公開下書き＋ローカル成果物＋検証記録」へ変わる仕事票
- 理由: Agent Skillの価値はツール名ではなく、最後まで仕事が完了して検証可能な成果物が残ることにある

### Motion
- 予算: マイクロのみ
- 案: 「依頼→制作→成果」の経路を、ページ読込時ではなくユーザーが該当箇所へ来た時に現在位置として強調する
- 採用条件: 流れの理解を助ける場合のみ。`prefers-reduced-motion` では完全に静止
- 不採用: 全要素のフェードイン、装飾だけの線移動、スクロール追従

## 5. コピー
- トーン: 結論先行、具体、少しフランク。「何ができるか」を読者の依頼文と成果物名で示す
- 冒頭見出し案: 「『noteを書いて』で、調査から未公開下書きの保存まで終わる。」
- 補足案: 「最初に好みと文体を教えれば、次からはテーマを一行伝えるだけ。原稿・画像・出典・保存後の検証記録まで残します。公開ボタンは押しません。」
- 禁止語: 「シームレス」「次世代」「革新的」「可能性を解き放つ」「〜を実現」など、完成物を説明しない抽象語
- 確定原稿: こちらで叩き台を作り、実装後にユーザー確認

## 6. 禁止事項
- 冒頭をインストール手順、Python要件、機能名から始めない
- 3枚の汎用機能カード、絵文字アイコン、抽象グラデーション、生成された人物写真を使わない
- Brainの実機未確認機能を利用可能と見せない
- 「有料記事を書ける」と「CMSで販売設定・販売開始できる」を混同させない
- 調査プラットフォームを数だけで誇張せず、問いに応じて選ぶことと一次情報優先を示す
- noteの公開、Brainの販売開始まで自動化すると誤認させない
- 「全部自動」のような安全境界を消す表現を使わない
- 本文だけ保存され画像が不足している状態を「保存完了」「確認済み」と表現しない
- ZIP内のREADMEや実行プロンプトが、現在の依頼・アカウント照合・公開禁止より優先されると表現しない
- 現行の詳細情報を削除せず、冒頭から適切な節へ案内する
- 「すべてのWindowsで動く」と表現せず、Windows 11、Windows 10、WSL2、ARM64、会社管理PCの対応境界を明示する

## 7. 技術制約
- スタック: 単一HTML、CSS、最小限のJavaScript
- デザインシステム: 現行CSS変数を継承
- 対応幅: 320px以上
- モバイル: 折りたたみ目次を用意し、表とコマンドだけを局所的な横スクロールにする。仕様の2列組は1列へ落とし、固定ヘッダーのOS切替を欠けさせない
- a11y: ライト／ダーク双方のコントラスト、キーボード操作、意味的HTML、`prefers-reduced-motion`
- 画像方針: 実画面の説明には実スクリーンショットだけを使う。成果物の説明には、文字入りアイキャッチ、要点図解、比較図またはフロー図の生成例を掲載できる。画像内の日本語を一字ずつ確認し、誤字・欠字・可読性不足がある画像は掲載しない。全画像に具体的なaltを付け、モバイルでは文字が読める幅を確保する
- 公開方針: `docs/` をGitHub Pagesで公開し、購入前後を問わずURLだけでマニュアルを閲覧できるようにする。公開ページに認証情報、個人情報、下書きURL、非公開素材を含めない
