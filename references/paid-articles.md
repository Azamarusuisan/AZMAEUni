# Paid article contract

この契約はnoteとBrainに共通する「有料で読む価値のある記事を作る」ための設計である。CMSの販売開始を自動化する契約ではない。

## できること

テーマを受け取ったら、無料部分と有料部分を一つの記事として完成させる。

- 無料部分: 誰向けか、何が解決するか、根拠、記事で得られるもの、購入前に必要な注意点
- 有料部分: 再現できる手順、判断基準、具体例、テンプレート、チェックリスト、失敗時の対処
- 販売案: 価格案と理由、有料ライン候補、必要な場合の紹介率案

本文、画像、出典、価格案、有料ライン位置をローカル成果物へ残す。CMSが安全に操作できる場合は未公開下書きへ入力できるが、公開、販売開始、購入、権限変更は行わない。

## Access model

記事ごとの `brief.json` で次のどちらかへ解決する。

- `free`: 全文無料
- `paid`: 無料部分と有料部分を持つ

ワークスペース既定値には `ask_each_time` を保存できるが、記事ごとのBriefに残してはならない。その都度 `free` または `paid` を選ぶ。

有料記事は次を持つ。

```json
{
  "access": {
    "model": "paid",
    "purchase_promise": "購入後にできるようになること",
    "free_preview_delivers": ["無料部分だけでも分かること"],
    "paid_section_delivers": ["有料部分で渡す具体物"],
    "paywall_after": "## この先で分かること",
    "paywall_confirmed_at": null,
    "price": {
      "currency": "JPY",
      "proposal": 980,
      "rationale": "価格案の理由",
      "confirmed_at": null
    },
    "referral_rate": {
      "proposal_percent": null,
      "confirmed_at": null
    }
  }
}
```

`referral_rate` は対応CMSで必要な場合だけ使う。価格案は記事内容から提案できるが、確定値ではない。

## 無料部分の品質

無料部分は広告文だけにしない。購入しなくても次が判断できる内容にする。

1. 対象読者と対象外の読者
2. 解決する問題と、解決しない問題
3. 結論または方法の全体像
4. 根拠、実例、サンプルのいずれか
5. 有料部分に何が含まれるか
6. 前提条件、費用、時間、リスク

不安を煽る、重要な条件を有料部分へ隠す、途中の文を不自然に切る、無料部分で約束した成果物を渡さない、といった構成にしない。

## 有料部分の品質

有料部分には、無料情報の言い換えではなく実行可能な価値を置く。記事に合うものを二つ以上含める。

- 手順と順番
- 判断基準、比較表、計算方法
- そのまま使えるテンプレート、prompt、質問票、チェックリスト
- 実例、ケーススタディ、失敗例
- つまずいたときの分岐と復旧方法
- 更新履歴、参考資料、追加検証

結果を保証しない。収益、健康、法律、投資などの結果に影響する記事では、前提と限界を明示し、必要に応じて専門家への相談を促す。

## 価格案

価格案は次を根拠に作る。

- 有料部分で渡す具体物の量と独自性
- 読者が短縮できる時間や避けられる失敗
- 調査、検証、更新にかかる負担
- 対象CMSの現行ルールと設定可能範囲

他人の記事や前回記事の価格を、そのまま既定値にしない。最終価格は利用者が記事ごとに確認する。割引、返金、紹介率、限定公開などがある場合も、内容と条件を本文で誤認なく説明する。

## 有料ライン

`paywall_after` は `outline.md` と `article.md` に存在する見出しを指定する。無料部分で購入判断に必要な情報を出したあと、有料部分の最初の見出し直前へ置く。

`paid-plan.md` へ次を残す。

```markdown
# Paid plan

- 購入後にできること: ...
- 有料ライン直前の見出し: ...
- 価格案: JPY 980
- 価格案の理由: ...
- 価格確認: 未確認
- 有料ライン確認: 未確認
```

価格、有料ライン、紹介率を利用者が今回のrunで確認したら、対応する `confirmed_at` を保存する。単なるBrief確認時刻を流用しない。

## 自動化モード

- `guided`: 記事の執筆は進められる。CMSへ進む前に価格と有料ラインを別々に確認する。
- `autopilot`: 無料・有料部分、価格案、`paid-plan.md` までは作れる。CMSへの入力前に `waiting_user` で停止する。
- 定期実行: 有料記事のローカル成果物まで作れる。価格、有料ライン、紹介率を確定せず、CMSを変更しない。

有料記事をCMSへ入力できるのは、`guided` の同席実行で、価格と有料ラインが今回のrunで確認済みの場合だけである。

## CMSごとの差

- note: 記事本文と有料設計を作れる。現行adapterは販売設定画面へ移動しないため、価格と有料ラインのCMS設定は人が行う。設定画面の安全な実機観察が完了するまで、この制約を緩めない。
- Brain: 記事本文と有料設計を作れる。価格、紹介率、有料ラインの入力は [cms-brain.md](cms-brain.md) の能力確認と規約由来の制約に従う。現在の実装状態を超えて「自動保存できた」と報告しない。

どちらも、未公開下書きであっても本人の確認なしに販売条件を推測または確定しない。
